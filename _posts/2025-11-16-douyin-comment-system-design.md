### 核心概念
短视频评论系统需同时满足高并发写入、低延迟读取和复杂展示（楼中楼、热度排序）。加入好友关系后需实现个性化排序与权限控制。

### 原理或源码关键点
1. **数据模型**：评论表拆为主评论与子评论，使用雪花 ID + 根节点引用；热度字段包括点赞数、时间、权重。好友关系存于图服务（如 Nebula/Redis Graph）或 Redis Set。
2. **写入链路**：评论写入采用 MQ 异步落库（MySQL + 分表），Redis Hash 存储热点评论内容；楼层计数使用 Redis INCR 并按段落刷新。
3. **读取链路**：按视频维度分片缓存 TopN 评论（按热度排序），长尾评论从 ES/ClickHouse 分页拉取。子评论采用批量预取以减少 N+1。
4. **好友增强**：读取时先查询好友评论 ID 列表，合并到结果集中，并按“好友优先 > 热门 > 时间”排序；权限上为好友评论添加私密标签并在接口层校验。
5. **反垃圾**：接入敏感词检测 + 风控模型；对同一用户评论频率限流，并通过内容相似度判定刷屏。

### 性能与分布式考量
- 评论写库按视频 ID Hash 分库，冷热分离：热点视频缓存读写，冷视频走对象存储 + CDN。
- 评论服务多活部署，依靠一致性哈希路由请求；好友数据可引入边缓存（Guava + Redis）减少查询延迟。
- 可观测性：埋点统计评论成功率、延迟、失败原因，自动触发限流或降级（如仅返回缓存）。

### 示例与总结
```sql
CREATE TABLE comment (
  id BIGINT PRIMARY KEY,
  video_id BIGINT,
  root_id BIGINT,
  parent_id BIGINT,
  content VARCHAR(500),
  heat_score DOUBLE,
  ctime TIMESTAMP
) PARTITION BY HASH(video_id);
```
抖音评论系统的关键是“数据分层 + 缓存 + 图关系”：写入异步化、读取缓存化，好友关系通过图数据提升排序体验，并结合风控与多活部署确保体验与安全。
