### 核心概念
短链服务将长 URL 映射为短码，并在全球或多机房环境中提供低延迟、可靠跳转。关键关注短码生成、一致性存储、跨机房路由与监控追踪。

### 原理或源码关键点
1. **短码生成**：使用发号器（Segment/Leaf/Snowflake）或基于自增 ID 的 Base62 编码；为避免碰撞需加上校验位或冲突检测。
2. **存储架构**：冷热分层——热数据保存在多活 Redis/ScyllaDB，冷数据落盘 MySQL + TiKV；通过双写或 binlog 同步保持一致性。
3. **多活路由**：DNS/GSLB 按地域路由到最近机房，机房内通过 Nginx + Consul/Etcd 做服务发现；若本地查不到短码则回源其他机房或对象存储。
4. **写路径**：写操作走强一致链路（如 Paxos/Raft 的 KV 存储）或使用全局事务消息，确保短码唯一；可在本地生成后异步同步，若冲突则回滚重试。
5. **跳转链路**：缓存命中即 302 跳转；未命中则查询存储并回填缓存。为防滥用，引入访问频控与风控名单。

### 性能与分布式考量
- **数据一致性**：多活场景建议采用主主复制 + 冲突解决策略（短码不可重复，可直接拒绝冲突写）。
- **延迟优化**：短链跳转用全局 Anycast + CDN；还可在客户端 SDK 内嵌短链解析表减少首跳。
- **容灾**：机房级故障时通过 GSLB 将流量切换至备机房；数据层采用多副本 + 冷热备份。定期做演练验证 RPO/RTO。
- **安全**：短链新增风控参数（签名、过期时间、访问次数）并记录审计日志。

跨机房短链的设计要点是“全球路由 + 多活存储 + 强一致发号 + 完整监控”：通过多层缓存、异地容灾与安全防护实现低延迟、高可靠和可审计的短链服务。
