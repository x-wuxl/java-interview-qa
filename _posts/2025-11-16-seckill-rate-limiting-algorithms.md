### 核心概念
限流的目标是在超高并发秒杀中控制系统入口流量，保护核心链路稳定运行。常用算法包括固定窗口、滑动窗口、令牌桶、漏桶以及基于队列/优先级的削峰算法。

### 原理或源码关键点
1. **固定窗口 / 滑动窗口**：通过 Redis INCR + EXPIRE 统计窗口内请求数，滑动窗口可拆分成多个小窗口加权求和以避免“临界突刺”。
2. **令牌桶（Token Bucket）**：Guava RateLimiter 或 Sentinel 通过后台定时补充令牌，允许一定突发量；消费令牌失败即拒绝或排队。
3. **漏桶（Leaky Bucket）**：请求进入漏桶后以固定速率流出，可用阻塞队列 + 定时消费实现，适合下游处理速率恒定的链路。
4. **队列削峰**：Nginx/Lua 或 MQ 在入口处将超出令牌的请求入队，后端按容量消费，控制排队长度避免雪崩。

### 性能与分布式考量
- 多机房部署要保证限流状态一致，可通过 Redis Cluster/etcd 做集中计数，或使用一致性哈希在本地分片限流。
- 秒杀需配合用户维度、IP 维度的细粒度限流，并结合熔断/降级策略；热点 Key 建议预分片或接入多级缓存。
- 监控拒绝率与成功率，动态调参（如令牌填充速率）并接入自动扩容。

### 示例与总结
```java
RateLimiter limiter = RateLimiter.create(1000.0); // 每秒 1000 个令牌
if (limiter.tryAcquire(1, 5, TimeUnit.MILLISECONDS)) {
    handleRequest();
} else {
    return failFast();
}
```
秒杀限流需“算法 + 架构”组合拳：入口基于窗口或令牌桶限流，中间队列削峰，后端结合熔断与动态扩容，确保业务稳定与用户体验平衡。
