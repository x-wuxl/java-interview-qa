### 核心概念
优惠券防刷的目标是限制恶意批量领取/核销，确保权益公平。主要手段包括限流、幂等、防重、用户画像与设备指纹等。

### 原理或源码关键点
1. **幂等写入**：领取接口以 `userId + couponId` 作为唯一键，利用 Redis SETNX 或数据库唯一约束保证只生成一次记录。
2. **多级限流**：网关按 IP、设备、账号设置速率阈值；对热点券使用队列削峰 + 随机延迟，避免机器人瞬时刷爆。
3. **风控画像**：实时埋点进入 Flink，计算风险特征（领取频次、券转售关联关系），高风险用户写入黑名单或提高领券门槛。
4. **设备指纹**：整合 UA、IP、定位、硬件 ID 生成指纹，结合滑块/短信验证进行二次校验。
5. **核销校验**：券码状态机（未领、已领、已用、失效），核销时走事务消息或 TCC，防止并发写入造成重复核销。

### 性能与分布式考量
- 领取入口采用 Redis + Lua 原子发放，库存采用预减策略并异步落库，若失败需补偿。
- 分布式环境下使用一致性 ID（雪花算法）跟踪券码流转，便于审计；跨机房通过多活架构 + 最终一致性消息队列同步状态。
- 日志与监控：Prometheus 监控领取成功率、拒绝率；异常突增时自动触发开关或切换白名单模式。

### 示例与总结
```lua
-- Redis Lua 限制同一用户重复领取
do
  local key = KEYS[1] -- user:coupon
  if redis.call('EXISTS', key) == 1 then
    return 0
  end
  redis.call('SET', key, 1, 'EX', ARGV[1])
  redis.call('DECR', KEYS[2]) -- 券库存
  return 1
end
```
防刷方案需“前置限流 + 中间风控 + 后置幂等”，配合日志追踪与补偿机制，实现对优惠券全生命周期的可控与可追溯。
